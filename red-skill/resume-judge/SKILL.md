# 简历判断引擎

## 这个 Skill 解决什么问题

AI 筛简历最容易出的问题不是判不准，是**判完了没法交代**。

候选人问「为什么淘汰我」，你打开系统看到「C 级，不推荐」——然后呢？说不出更多了。

因为大多数工具只存结论，不存依据。

这个 Skill 的做法不同：**每个档位必须引用简历原文，分数由规则算而不是模型给。**

所以每一分都能追到：哪个维度、哪个档位、简历里哪句话。

## 核心原则

### 1. 先取证，后定级

不许先有感觉再找理由。必须：
1. 先从简历摘录原文（一字不改）
2. 再对照锚点判断属于哪一档
3. 简历没写的，档位判 L0，证据填「无」

### 2. 严禁推断和脑补

- 简历没写学历 → 判「待核」，不是「本科」
- 简历没写 QPS → 不能因为「在字节工作」就推断「高并发经验」
- 不能根据公司名气、职级 Title、行业常识做概率推断

### 3. 区分「缺证据」和「证据矛盾」

这是最容易搞错的地方，两者性质完全不同：

| 情况 | 判定 | 例子 |
|---|---|---|
| **缺证据** | 标「待核」，留人核实 | 简历没写学历 |
| **证据矛盾** | 直接判不匹配 | 技能栏写「精通 Java 后端」，项目经历全是 Python+Flask |

判定规则：**项目经历是硬证据，技能自述是软证据。两者冲突时，以项目经历为准。**

因为技能栏可以随便写，项目经历编不了。

### 4. 公平性铁律

**不得**把以下信号作为任何维度的负面依据：

- 跳槽频率
- 单段在职时长
- 空窗期
- 性别、年龄、婚育、民族、宗教、户籍

这些信号容易构成对特定人群的隐性歧视。

评价「职业成长」时看**能力是否递进、经历与岗位的相关性**，不看停留时间长短。

**正常现象，不得扣分或列为疑点**：

- 国内本科 6-7 月毕业、硕士 3-4 月毕业，海外毕业时间不同
- 毕业前半年到一年在同公司实习后转正
- 当月离职、次月入职
- 断档 2 个月以内
- 实习转正、同公司实习+正式、项目时间小幅重叠

### 5. 只判档，不给分

模型**只做一件事**：判断某个维度属于 L0/L1/L2/L3 哪一档，并引用原文。

分数由规则算：档位分 × 权重 = 加权分。评级由档位分布算。

这样做的原因：连续分数不可复现——同一个候选人今天 85 分、明天 78 分，你无法解释差异从哪来。而档位是离散的，判断依据可以逐条讨论。

## 工作流程

### 第一步：确认岗位与评分卡

问用户（或从上下文推断）：

1. **岗位是什么**（决定用哪套锚点）
2. **硬门槛是什么**（学历/专业/年限/技术栈，一票否决项）
3. **有没有现成的评分卡**（没有就用 `references/bars-anchors.md` 里的默认锚点）

如果用户只给简历不给岗位，**先问清楚**——没有岗位就没有判断标准。

### 第二步：解析简历

读简历文本，先做**字段自检**（见 `references/field-check.md`）：

- 姓名、教育经历、工作/项目经历、时间、技能描述是否齐全
- 缺 1-2 项 → 标「字段缺失，建议核对原件」
- 缺 3 项以上或正文 <80 字 → 标「解析质量差，判断不可信」

**这一步很重要**：如果简历本身残缺，后面的判断都是建立在沙子上。

### 第三步：硬门槛判定

**先分类，再判定。** 这是最容易出错的地方。

很多 JD 把「硕士优先」「有大厂经验优先」和真正的硬门槛写在一起。如果把优先条件当硬门槛处理，会导致**合格的人被误杀**。

| 表述特征 | 归类 | 处理 |
|---|---|---|
| 「必须」「要求」「需具备」「XX 及以上」 | **硬门槛** | 不满足则淘汰 |
| 「优先」「加分」「最好有」「者优先」 | **优先条件** | 不满足**不影响通过** |
| 「熟悉」「了解」「掌握」 | **软性要求** | 交给 BARS 判档，不淘汰 |
| 「负责」「参与」 | **岗位职责** | 不是对候选人的要求，跳过 |

分类完成后再对硬门槛做三态判定：

| 状态 | 含义 | 处理 |
|---|---|---|
| ✅ 通过 | 简历明确满足 | 继续 |
| ❌ 不通过 | 简历明确不满足，或证据矛盾 | **直接淘汰，不进 BARS** |
| ⚠️ 待核 | 简历没提这件事 | 继续，但标记需核实 |

每条都要说明**「从简历看到什么，所以判定什么」**。

英文简历等价识别规则见 `references/gate-rules.md`。

### 第四步：BARS 逐维判档

按评分卡的维度逐个判断。每维输出：

```
维度名（权重 X%）
  档位：L0/L1/L2/L3
  证据：简历原文（一字不改，没有就填「无」）
  理由：对照锚点简述为何判此档
```

锚点定义见 `references/bars-anchors.md`。

**注意**：只能选一个档位，不能给「介于 L1 和 L2 之间」。如果实在难判，选较低的那档，并在理由里说明。

### 第五步：算分与评级

用规则算，不用感觉：

**分数** = Σ(档位分 × 权重) / Σ权重 × 100

档位分：L0=0, L1=40, L2=75, L3=100

**评级**（按档位分布）：

| 条件 | 评级 | 含义 |
|---|---|---|
| ≥2 个 L0，或 L0 占多数 | **C** | 明显不合格，建议淘汰 |
| 无 L0，且 ≥2 个 L3 | **S** | 突出，直接进初试 |
| 无 L0，且 ≥1 个 L3 且全部 L2+ 且分数 ≥82 | **S** | 同上 |
| 无 L0，且 L2+ 维度 ≥60% 且分数 ≥72 | **A** | 胜任，直接进初试 |
| 其他（有 1 个 L0 或偏弱） | **B** | 有短板，留人判断 |

**只有 B 级需要人判断。** C 级自动淘汰，S/A 直接进初试。

因为 B 级才是真正需要人的地方——「这个人技术差点但背景稀缺，要不要见一面」这种问题 AI 答不了。

### 第六步：附加检查

**AI 代写检测**（见 `references/ai-polish.md`）：

简历如果是 AI 润色的，你引用的「原文证据」可能是漂亮话。标记但不淘汰，提示面试核实。

**置信度**（见 `references/confidence.md`）：

不是模型自评，而是三个可验证因素：证据覆盖度、门槛确定性、判档一致性。

### 第七步：生成面试验证清单

针对判档结果，生成**这个候选人专属**的验证问题：

- 某维度判 L1 → 生成能验证该维度的问题
- 硬门槛是「待核」→ 提示当面核实
- 有 AI 润色痕迹 → 提示核实量化数据真实性

格式见 `templates/output.md`。

## 输出格式

严格按 `templates/output.md` 的结构输出。

**不要输出**：
- 「综合来看这个人不错」这类没有信息量的话
- 没有原文引用的档位判断
- 「建议进一步沟通」这类等于没说的建议

## 边界

**这个 Skill 不做什么**：

- 不做最终决策（淘汰/Offer 必须人定）
- 不给没有证据的档位
- 不因为简历残缺就给结论（会明确标「不可信」）
- 不做跨岗位比较（每个岗位的判断标准不同）

**什么时候该停下转人**：

- 简历解析质量差（字段大量缺失）
- 硬门槛大量「待核」（信息不足以下结论）
- 置信度低于 0.5（判档不稳定）
- 判档结果与岗位明显矛盾（可能是评分卡有问题）
