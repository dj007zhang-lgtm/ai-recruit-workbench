# AI 代写 / 过度润色检测

> 为什么要在简历判断里做这件事？
>
> 因为本 Skill 的核心机制是「判档 + 引用原文证据」。
> 如果简历本身是 AI 润色甚至重写的，你引用的「原文证据」可能是漂亮话而非事实——整条证据链的可信度被动摇。

## 检测思路

**不追求判定「是否 AI 写的」**（这不可靠），只标记**文本特征异常**，提示面试时重点核实量化数据。

宁可误标，不可漏标——因为漏标代价更高。

## 五项检测信号

### 1. 企业黑话密度

统计以下词的出现次数，≥3 个不同词则标记：

```
赋能、闭环、抓手、打法、组合拳、生态位、护城河、飞轮、第二曲线、
底层逻辑、顶层设计、方法论、颗粒度、对齐、拉通、沉淀、复用、范式、势能
```

英文版：`leveraging`、`synergy`、`paradigm shift`、`best-in-class`、`cutting-edge`、`seamless`

**为什么**：AI 润色喜欢堆这类词，因为它们「看起来专业」但没有具体信息。

### 2. 排比/对仗句式密集

统计以下模式的出现次数，≥3 处则标记：

```
不仅……而且……
一方面……另一方面
既……又……
从……到……
```

**为什么**：AI 生成的文本偏爱工整的排比结构，人工写作通常更参差。

### 3. 形容词多但量化数据少

统计：
- 形容词数量：深入、全面、显著、大幅、有效、充分、高度、极大、卓越、优异、出色、完善
- 量化数据数量：数字 + 单位（% / 万 / 千 / 亿 / ms / s / QPS / TPS / 人 / 倍）

**判定**：形容词 ≥5 处 **且** 量化数据 ≤2 处 → 标记

**为什么**：AI 润色的典型特征是「形容词多、数字少」——因为数字要基于事实，形容词不用。

### 4. 段落长度高度一致

计算各段落长度的变异系数（标准差 / 平均值）。

**判定**：变异系数 < 0.28 → 标记

**为什么**：人工写作的段落长度通常参差不齐（有的详写、有的略写），AI 生成的更均匀。

### 5. 装饰符号密集

统计 ✅ 🎯 📌 🔹 🔸 ▶ ● ◆ 等符号，≥6 个则标记。

**为什么**：AI 润色的简历喜欢用装饰符号分段，显得「结构化」。

## 分级

| 命中信号数 | 分级 | 含义 | 处理 |
|---|---|---|---|
| 0 | clean | 未见异常 | 正常判断 |
| 1-2 | suspect | 有润色痕迹 | 面试时留意 |
| ≥3 | likely | 高度接近 AI 生成 | 面试须核实量化数据真实性 |

## 输出格式

```
AI 润色检测：suspect（2 项特征）
  · 企业黑话密集（赋能、闭环、方法论、颗粒度）
  · 形容词多（11 处）但量化数据少（0 处）
  → 有 AI 润色痕迹，建议面试时重点核实项目数据
```

## 重要提醒

**标记不等于淘汰。**

即使检测出 likely，也不能因此判 C 或淘汰。原因：

1. 检测本身有误报可能（有些人写东西就是工整）
2. 「用 AI 润色简历」不是道德问题，是普遍现象
3. 真正该做的是**面试核实数据**，不是拒绝

所以这条检测的唯一作用是：**提醒面试官该重点问什么**。
