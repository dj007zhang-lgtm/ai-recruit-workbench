# BARS 行为锚定档位定义

> 锚点的作用：把「优秀」「熟练」这类形容词，翻译成**可观察、可验证的行为**。
>
> 判档时只能对照这些行为描述，不能凭感觉。

## 通用四维（研发/技术岗默认）

### 1. 过往战绩与量化成果（权重 40%）

| 档位 | 判定标准 | 档位分 |
|---|---|---|
| L0 | 仅罗列技术职责，无任何性能/规模/成果数据 | 0 |
| L1 | 提及系统/项目但无指标或体量 | 40 |
| L2 | 有可核实的技术指标（QPS/延迟/可用性）或项目规模数据 | 75 |
| L3 | 大规模/高复杂度系统下实现显著指标提升并有归因 | 100 |

**判档要点**：
- 「负责订单模块开发」→ L0（只有职责）
- 「参与电商平台开发」→ L1（有项目但无量级）
- 「优化查询接口，响应时间从 8s 降至 1s」→ L2（有具体指标）
- 「支撑日均 500 万订单，通过分库分表将 P99 从 800ms 降至 120ms」→ L3（大规模 + 显著提升 + 归因）

### 2. 技能与专业深度（权重 30%）

| 档位 | 判定标准 | 档位分 |
|---|---|---|
| L0 | 无岗位核心技术栈描述 | 0 |
| L1 | 会用语但无深度案例 | 40 |
| L2 | 精通核心栈且有架构/性能/复杂问题解决案例 | 75 |
| L3 | 技术深度突出，主导过关键系统设计或技术突破 | 100 |

**判档要点**：
- 只列「熟悉 Java、Spring、MySQL」→ L0（技能清单不算深度）
- 「使用 Spring Boot 开发接口」→ L1（会用语，无案例）
- 「主导微服务拆分，将单体应用拆为 6 个服务，设计服务间通信方案」→ L2（有架构案例）
- 「主导分布式事务方案设计，解决跨服务数据一致性问题」→ L3（关键技术突破）

### 3. 行业与赛道匹配（权重 20%）

| 档位 | 判定标准 | 档位分 |
|---|---|---|
| L0 | 无相关行业/业务形态经历 | 0 |
| L1 | 相关技术但业务形态不同 | 50 |
| L2 | 目标行业/相近业务形态头部经历 | 100 |

**判档要点**：
- 做金融系统，投电商岗 → L1（技术相关，业务不同）
- 做电商 SaaS，投电商平台 → L2（业务形态相近）
- 做 To B 后台，投 To C 产品 → L1

**注意**：这一维只有三档（无 L3），因为「行业匹配」没有「超出预期」这一说。

### 4. 职业成长与经验积累（权重 10%）

| 档位 | 判定标准 | 档位分 |
|---|---|---|
| L0 | 经历与岗位所需能力无关联，看不出积累方向 | 0 |
| L1 | 有相关经历，能力有一定积累 | 60 |
| L2 | 经历层层递进，能力持续迭代与拓宽 | 100 |

**判档要点**：
- 看**能力是否递进**，不看**在职时长**
- 「从初级开发到技术负责人，负责范围从模块扩大到系统」→ L2
- 「三段经历都在做相同的 CRUD」→ L1

**红线**：不得因为「跳槽频繁」「某段只做了 8 个月」判 L0。这是隐性歧视。

## 其他岗位族的锚点

### 零售/门店岗

**过往战绩与量化成果（40%）**
| 档位 | 判定标准 |
|---|---|
| L0 | 仅罗列门店日常职责，无任何业绩/人效/损耗数据 |
| L1 | 提及销售额/客诉等指标，但无具体数字或归因 |
| L2 | 给出可核实的门店业绩/人效/损耗改善量化结果 |
| L3 | 多店或规模化场景下实现显著量化提升（如扭亏/GMV大幅增长）|

**技能与专业深度（30%）**
| 档位 | 判定标准 |
|---|---|
| L0 | 无门店运营相关技能描述 |
| L1 | 提及排班/陈列/客诉等单项技能 |
| L2 | 覆盖排班+目标拆解+客诉+损耗中多项，有实操案例 |
| L3 | 全链路精通且能沉淀方法/带教他人 |

### 电商岗

**过往战绩与量化成果（40%）**
| 档位 | 判定标准 |
|---|---|
| L0 | 仅职责描述，无 GMV/ROI/转化等数据 |
| L1 | 提及 GMV/流量增长但无成本/ROI/毛利口径 |
| L2 | 有可核实的 GMV/ROI/转化率量化提升 |
| L3 | 规模化店铺/大促下实现显著增长且有归因 |

## 自定义评分卡

如果用户提供了自己的评分卡，**以用户的为准**。

判断用户的评分卡是否可用：

| 检查项 | 不合格的表现 |
|---|---|
| 锚点是否可观察 | 「熟悉」「精通」「优秀」这类无法证伪的词 |
| 档位是否互斥 | L1 和 L2 描述重叠，无法区分 |
| 是否有 L0 | 没有「无证据」这一档，会导致强给分 |

如果用户的评分卡有问题，**先指出问题，再建议修改**，不要直接套用。
