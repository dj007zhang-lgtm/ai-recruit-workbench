# 简历字段自检

> 为什么先做这一步？
>
> 简历解析错误会静默流到下游：AI 拿残缺文本判档 → 误判 → 你基于误判做决策。
>
> 在判断之前先检查「这份简历能不能用来判断」。

## 五项必备字段

| 字段 | 检查方式 | 缺失后果 |
|---|---|---|
| 姓名 | 正文是否出现 | 无法确认身份 |
| 教育经历 | 是否含「教育/学历/本科/硕士/博士/专科/大学/学院」 | 学历门槛无法判定 |
| 工作/项目经历 | 是否含「工作经历/项目经历/实习/任职/在职」 | 核心判断依据缺失 |
| 时间 | 是否含任何年份（19xx 或 20xx） | 年限、稳定性无法判断 |
| 技能描述 | 是否含「技能/技术栈/掌握/熟悉/精通/熟练/了解」 | 技术栈匹配失效 |

## 三档判定

| 缺失项数 | 正文长度 | 分级 | 处理 |
|---|---|---|---|
| 0 | ≥80 字 | **ok** | 可以正常判断 |
| 1-2 | ≥80 字 | **suspect** | 字段缺失，建议核对原件后再采信结论 |
| ≥3 | 任意 | **poor** | 解析质量差，判断不可信，请人工核对原件 |
| 任意 | <80 字 | **poor** | 同上 |

## 输出格式

```
字段自检：suspect
  · 未识别到工作/项目经历
  · 未识别到任何年份
  → 字段缺失，建议核对原件后再采信 AI 结论
```

## 什么时候该停下

**判为 poor 时，不要继续做 BARS 判档。**

原因：如果连「有没有工作经历」都识别不出来，判档就是瞎猜。

正确做法：
1. 明确告诉用户「这份简历解析质量差，判断不可信」
2. 列出缺失了哪些字段
3. 建议用户：提供更清晰的简历文本，或人工核对原件
4. **不要给评级**（给了一个假评级比不给更糟）

## 常见解析问题

| 现象 | 原因 | 表现 |
|---|---|---|
| 字段串行 | 双栏/多列排版 | 「教育经历工作经历项目经历」连成一行 |
| 时间丢失 | 表格形式 | 只抽出公司名，没有起止时间 |
| 技能遗漏 | 图标/进度条形式 | 技能用星级或进度条表示，文本抽取不到 |
| 内容缺失 | 扫描件未 OCR | 只有图片没有文本层 |

如果用户提供的是 PDF 或图片，先提示：「如果解析结果看起来乱，可能是排版导致的，建议提供纯文本版本。」
